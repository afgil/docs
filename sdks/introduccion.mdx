Tupana tiene SDKs oficiales para Node.js (TypeScript) y Python, publicados en npm y PyPI con el nombre `tupana` y con código abierto en GitHub.

| Lenguaje | Paquete | Instalación | Repositorio |
|---|---|---|---|
| Node.js / TypeScript | [`tupana` en npm](https://www.npmjs.com/package/tupana) | `npm install tupana` | [tupana-ai/tupana-node](https://github.com/tupana-ai/tupana-node) |
| Python | [`tupana` en PyPI](https://pypi.org/project/tupana/) | `pip install tupana` | [tupana-ai/tupana-python](https://github.com/tupana-ai/tupana-python) |

Ambos SDKs cubren la API v2: emisión de documentos en lote con `Idempotency-Key` automático, links de pago (recaudación), cesiones, webhooks con verificación de firma, reintentos con backoff ante `429` y `5xx`, y errores tipados. La referencia completa de métodos está en el README de cada repositorio.

## Instalación

<CodeGroup>

```bash Node.js
npm install tupana
```

```bash Python
pip install tupana
```

</CodeGroup>

El SDK de Node.js funciona en Node 18 o superior (también en Bun, Deno o cualquier runtime con `fetch`) y no tiene dependencias en runtime. El de Python requiere Python 3.9 o superior e incluye un cliente síncrono (`Tupana`) y uno asíncrono (`AsyncTupana`).

Guarda tu API key en la variable de entorno `TUPANA_API_KEY`: ambos clientes la leen de ahí si no se la pasas. Nunca la dejes en el código. Para obtener una, ver [Tu primera llamada en 2 minutos](/quickstart).

```bash
export TUPANA_API_KEY="tu-api-key"
```

## Emitir una factura

Con una key de sandbox la emisión se simula y no va al SII; con una de producción, el código es el mismo.

<CodeGroup>

```ts Node.js
import Tupana from "tupana";

const tupana = new Tupana({ apiKey: process.env.TUPANA_API_KEY });

const batch = await tupana.documents.createBatch(
  {
    documents: [
      {
        dte_type: { code: "33" }, // Factura electrónica
        document_issuer: { rut: "76543210-3" }, // tu empresa
        document_receiver: { rut: "77777777-7" }, // tu cliente
        details: [{ item_name: "Asesoría contable octubre", quantity: 1, unit_price: 150000 }],
      },
    ],
  },
  { useDefaults: true }, // la API completa razón social, giro, dirección, fecha y forma de pago
);

// En un script puedes esperar el resultado. En producción, usa webhooks.
const result = await tupana.documents.waitForBatch(batch.batch_id);
for (const doc of result.documents) {
  console.log(doc.index, doc.status, doc.document?.folio, doc.document?.pdf_url);
}
```

```python Python
from tupana import Tupana

tupana = Tupana()  # lee TUPANA_API_KEY

batch = tupana.documents.create_batch(
    [
        {
            "dte_type": {"code": "33"},  # Factura electrónica
            "document_issuer": {"rut": "76543210-3"},  # tu empresa
            "document_receiver": {"rut": "77777777-7"},  # tu cliente
            "details": [
                {"item_name": "Asesoría contable octubre", "quantity": 1, "unit_price": 150000}
            ],
        }
    ],
    use_defaults=True,  # la API completa razón social, giro, dirección, fecha y forma de pago
)

# En un script puedes esperar el resultado. En producción, usa webhooks.
result = tupana.documents.wait_for_batch(batch["batch_id"])
for doc in result["documents"]:
    print(doc["index"], doc["status"], (doc.get("document") or {}).get("folio"))
```

</CodeGroup>

Cada llamada a `createBatch` / `create_batch` acepta hasta 500 documentos y viaja con un `Idempotency-Key`. Si no pasas uno, el SDK genera un UUID; para reintentar con seguridad desde otro proceso, usa una key tuya y estable (`idempotencyKey` en Node.js, `idempotency_key` en Python).

## Otros endpoints

Para endpoints de la API v2 que todavía no tienen método propio (folios, libros del SII, nómina) usa `raw` en Node.js o `request` en Python, con la misma autenticación, reintentos y errores:

<CodeGroup>

```ts Node.js
const folios = await tupana.raw("GET", "/folios/", { query: { master_entity_id: "ment_4829301923847" } });
```

```python Python
folios = tupana.request("GET", "/folios/", query={"master_entity_id": "ment_4829301923847"})
```

</CodeGroup>

En Node.js, los tipos generados del OpenAPI completo están en `tupana/openapi`.

## Sin SDK: la API REST directa

Si prefieres no agregar una dependencia, la API es REST con JSON y cualquier cliente HTTP sirve. Lo único que necesitas es el header `Authorization: Api-Key <tu_key>`.

<CodeGroup>

```javascript Node.js (fetch)
const res = await fetch("https://api.tupana.ai/v2/documents/batch/", {
  method: "POST",
  headers: {
    Authorization: `Api-Key ${process.env.TUPANA_API_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": "pedido-1001",
    "X-Use-Defaults": "true",
  },
  body: JSON.stringify({
    documents: [{
      dte_type: { code: "33" },
      document_issuer: { rut: "76123456-7" },
      document_receiver: { rut: "77987654-3", business_name: "Cliente SpA" },
      details: [{ item_name: "Servicio", quantity: 1, unit_price: 100000 }],
    }],
  }),
});
console.log(res.status, await res.json());
```

```python Python (requests)
import os, requests

res = requests.post(
    "https://api.tupana.ai/v2/documents/batch/",
    headers={
        "Authorization": f"Api-Key {os.environ['TUPANA_API_KEY']}",
        "Idempotency-Key": "pedido-1001",
        "X-Use-Defaults": "true",
    },
    json={
        "documents": [{
            "dte_type": {"code": "33"},
            "document_issuer": {"rut": "76123456-7"},
            "document_receiver": {"rut": "77987654-3", "business_name": "Cliente SpA"},
            "details": [{"item_name": "Servicio", "quantity": 1, "unit_price": 100000}],
        }]
    },
)
print(res.status_code, res.json())
```

</CodeGroup>
