# Errores

La API v2 devuelve **un solo formato de error** en toda respuesta ≥ 400. Está
diseñado para que puedas manejar errores con código estable y sin parsear texto.

## Estructura del error

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "parameter_missing",
    "message": "Falta el parámetro requerido 'master_entity_id'.",
    "param": "master_entity_id",
    "resource": "ment_4829301923847",
    "doc_url": "https://docs.tupana.ai/v2/errors#parameter_missing",
    "request_id": "req_8f3a9c2b1e7d4"
  }
}
```

| Campo | Siempre | Descripción |
|-------|:------:|-------------|
| `type` | ✓ | Categoría amplia y **estable**. Mapea 1:1 al status HTTP (tabla abajo). |
| `code` | ✓ | Código específico, **estable, machine-readable**. Haz tu `switch` sobre esto. |
| `message` | ✓ | Texto para humanos (es-CL). **Puede cambiar — nunca lo parsees.** |
| `param` | — | Campo que causó el error (para formularios). |
| `resource` | — | **Public ID** del recurso involucrado (`docu_…`, `ment_…`, `cred_…`). |
| `doc_url` | ✓ | Link directo a la explicación de este `code`. |
| `request_id` | ✓ | ID de correlación (`req_…`). Inclúyelo al contactar soporte. |

<Warning>
Maneja los errores por **`code`** (estable), no por `message` (puede cambiar) ni
por el status HTTP solo (varios `code` comparten status).
</Warning>

## Tipos de error y status HTTP

| `type` | HTTP | Cuándo ocurre | ¿Reintentar? |
|--------|:----:|---------------|:------------:|
| `invalid_request_error` | 400 | Request mal formado o parámetro inválido | No — corrige el request |
| `authentication_error` | 401 | Falta la API Key o es inválida | No |
| `permission_error` | 403 | La API Key no tiene acceso a ese recurso | No |
| `not_found_error` | 404 | El recurso (public ID) no existe | No |
| `validation_error` | 422 | El documento no cumple una regla de negocio o del SII | No — corrige los datos |
| `conflict_error` | 409 | Estado conflictivo (folio/RUT duplicado) | No |
| `idempotency_error` | 409 | Reusaste una `Idempotency-Key` con un body distinto | No |
| `credential_error` | 400 | Credencial SII/certificado inválida, incompleta o bloqueada | Solo tras corregir la credencial |
| `sii_error` | 400 / 503 | El SII rechazó el documento o no está disponible | Sí si es `sii_unavailable` |
| `payment_error` | 400 | Problema al generar el cobro (pasarela / datos bancarios) | No |
| `rate_limit_error` | 429 | Superaste el límite de solicitudes | Sí — con backoff (ver `Retry-After`) |
| `api_error` | 500 / 502 / 503 | Error interno o de un servicio upstream | Sí — con backoff |

### Ejemplo de manejo (pseudo)

```python
resp = tupana.documents.create(batch)
if resp.status_code >= 400:
    err = resp.json()["error"]
    if err["code"] == "folios_exhausted":
        alertar_contador("Solicita más CAF en el SII")
    elif err["type"] == "rate_limit_error":
        reintentar_con_backoff(resp.headers["Retry-After"])
    elif err["type"] == "sii_error" and err["code"] == "sii_unavailable":
        reintentar_mas_tarde()
    else:
        log(err["request_id"], err["message"])
```

## Catálogo de códigos

<Note>
Los códigos de **Comunes**, **Cesiones** y **Recaudación** ya se emiten en
producción. Las secciones marcadas con **⏳** están en implementación: hoy esos
endpoints devuelven `parameter_missing`/`parameter_invalid` en errores de campo
(con `param`) y `validation_error` con mensaje en reglas de negocio; los códigos
específicos listados se están desplegando.
</Note>

### Comunes (todas las APIs)

| `code` | `type` | HTTP | Significado |
|--------|--------|:----:|-------------|

| `parameter_invalid` | invalid_request_error | 400 | Un parámetro tiene formato o valor inválido (ver `param`). |

| `forbidden` | permission_error | 403 | La API Key no tiene acceso a ese recurso. |
| `resource_missing` | not_found_error | 404 | El public ID no existe (ver `resource`). |

| `rate_limited` | rate_limit_error | 429 | Demasiadas solicitudes. Respeta `Retry-After`. |
| `internal_error` | api_error | 500 | Error interno. Reintenta; si persiste, reporta el `request_id`. |

### ⏳ Facturación — Guía de despacho (DTE 52) y líneas exentas

Estas validaciones responden **422** con `type` `validation_error`. No tienen un
`code` propio: usa `type` y `param` (o el mensaje, sólo para mostrarlo) para
identificar el campo.

| Caso | HTTP |
|------|:----:|
| `transport_data.transport_type` fuera de `"1"`–`"9"` o `dispatch_type` fuera de `"1"`–`"3"` | 422 |
| `dispatch_type` con `transport_type` `"5"` (traslado interno) | 422 |
| `transport_rut` o `driver_rut` inválido, o sólo uno de `driver_rut` / `driver_name` | 422 |
| `destination_address` > 70, `destination_district` > 20 o `destination_city` > 20 caracteres | 422 |
| Datos de Aduana (`departure_port_code`, `arrival_port_code`, `gross_weight`, `gross_weight_unit_code`, `total_packages`, `package_type_code`) con `transport_type` distinto de `"8"`/`"9"` | 422 |
| Traslado `"8"`/`"9"` sin puertos, peso bruto o unidad, con emisor del facturador de mercado | 422 |
| Puerto, unidad o tipo de bulto fuera de las tablas de Aduana; `gross_weight` o `total_packages` ≤ 0; `total_packages` sin `package_type_code` | 422 |
| `details[].is_exempt` en un documento que no es DTE 52 | 422 |
| `dispatch_type`, `destination_*`, datos de Aduana o `details[].is_exempt` con emisor del **facturador gratuito del SII**: *"no disponible para emisores del facturador gratuito del SII"* | 422 |

Detalle de cada campo en [Emisión masiva de documentos (v1)](/api-reference/documents/batch), bloque "Guía de Despacho (DTE 52)".

### ⏳ Facturación — Campos desconocidos

Un campo que no existe en el documento (por ejemplo `header.transfer_indicator`)
**no se usa al emitir**. Según la API key:

- **Modo aviso** (integraciones existentes): el documento se crea sin ese campo
  y la respuesta del batch trae un arreglo `warnings`. No es un error: el status
  es el de un batch aceptado.
- **Modo estricto** (API keys nuevas): la API responde **422** `validation_error`
  y el documento no se crea.

```json
{
  "warnings": [
    {
      "document_index": 0,
      "field": "header.transfer_indicator",
      "code": "unknown_field",
      "message": "Campo desconocido: se ignoró.",
      "suggestion": "transport_data.transport_type"
    }
  ]
}
```

| Campo | Descripción |
|-------|-------------|
| `document_index` | Posición del documento en `documents` (desde 0). |
| `field` | Ruta del campo dentro del documento. |
| `code` | Tipo de aviso. Hoy siempre `unknown_field`. |
| `message` | Texto para humanos. **Puede cambiar — nunca lo parsees.** |
| `suggestion` | Campo correcto si se reconoce el error, o `null`. |

| Campo enviado | `suggestion` |
|---------------|--------------|
| `header.transfer_indicator` | `transport_data.transport_type` |
| `export_data.export_clause` | `export_data.sale_clause_code` |
| `export_data.destination_country` | `export_data.destination_country_code` |

<Warning>
Un aviso significa que el dato **no llegó al documento**: con
`header.transfer_indicator` la guía sale como venta (`transport_type` `"1"`) y con
`export_data.export_clause` la factura de exportación sale sin cláusula de venta.
</Warning>

## Idempotencia y errores

Los endpoints de escritura (emisión, cobros) aceptan el header `Idempotency-Key`.
Si reintentas **con la misma key y el mismo body**, la API devuelve la respuesta
original **sin repetir la operación** (no se re-emite al SII). Si reutilizas la
misma key con un **body distinto**, obtienes `idempotency_key_reused` (409).
