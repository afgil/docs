---
title: "Listar instituciones"
openapi: "api-reference/openapi-v2.json GET /institutions/"
---

Los bancos que una empresa puede conectar con
[Tupana Connect](/api-reference/v2/connect/tupana-connect) y qué entrega cada uno. Es
el mismo catálogo que ve el usuario final en el widget.

```bash
curl https://api.tupana.ai/v2/institutions/ \
  -H "Authorization: Api-Key TU_API_KEY"
```

```json
{
  "data": [
    {
      "code": "cl_banco_falabella",
      "name": "Banco Falabella",
      "source": "scraper",
      "status": "available",
      "capabilities": {
        "balances": true,
        "movements": true,
        "cards": false,
        "payments": false
      }
    }
  ]
}
```

## Qué dice cada campo

- `code` identifica al banco en toda la API: es el que verás en las conexiones y,
  más adelante, en cada cuenta y movimiento.
- `source` es el conector con que Tupana lee ese banco. Es informativo: no
  cambia lo que recibes.
- `status` es `available` cuando el banco entrega datos, y `coming_soon` cuando
  Tupana todavía solo guarda la credencial para integrarlo después.
- `capabilities` dice qué se lee: `balances` y `movements` hoy; `cards` y
  `payments` vienen en falso hasta que existan, para que tu integración ya
  tenga el contrato.

<Info>
El banco de pruebas de sandbox no aparece acá: con una API key de sandbox las
conexiones se fabrican sin elegir banco.
</Info>
