Las empresas conectadas a tu integración. Una conexión es lo único que tu SaaS
conoce de una empresa: nunca ves la clave del SII, porque la entrega el usuario
final dentro de [Tupana Connect](/api-reference/v2/connect/tupana-connect).

Es además el paso **empresa emisora** de cualquier flujo. Cada conexión trae el
giro, su código y la dirección, así que no necesitas guardarlos: mandas
`company_id` al emitir y la API completa el emisor.

## Buscar

`?search=` filtra por nombre o RUT, con un mínimo de 2 caracteres: con una
letra, "buscar" sería traer todo. Menos de 2 responde `400`.

```bash
curl https://api.tupana.ai/v2/connections/?search=arquitectura \
  -H "Authorization: Api-Key TU_API_KEY"
```

## Paginar

La respuesta usa el mismo envelope que el resto de los listados v2:

```json
{
  "data": [
    {
      "connection_id": "cred_2959001189629508554",
      "company_id": "ment_3672486436546233854",
      "type": "tax",
      "provider": "sii",
      "status": "active"
    }
  ],
  "meta": { "page": 1, "page_size": 25, "total": 31, "total_pages": 2 },
  "links": {
    "next": "https://api.tupana.ai/v2/connections/?page=2",
    "prev": null
  }
}
```

`page_size` viene en 25, se acota a 100 y corta conexiones, no empresas
(`limit` se acepta como alias). `meta.total` es cuántas conexiones calzan con
tus filtros: una empresa con su conexión tributaria y una de banco son dos. Va
aparte del largo de `data` a propósito, así te enteras si tienes más
conexiones de las que pediste. Para la página siguiente sigue `links.next`
hasta que venga `null`.

```bash
curl "https://api.tupana.ai/v2/connections/?page=2&page_size=25" \
  -H "Authorization: Api-Key TU_API_KEY"
```

<Note>
La respuesta ya no trae `total` ni `limit` en la raíz. Lee `meta.total` y
`meta.page_size`.
</Note>

## Filtrar por empresa

`?company_id=` trae solo las conexiones de esa empresa: el `company_id`
(`ment_…`) que devuelve este mismo listado. También se acepta
`master_entity_id`. Una empresa que no es tuya responde una lista vacía.

```bash
curl "https://api.tupana.ai/v2/connections/?company_id=ment_3672486436546233854" \
  -H "Authorization: Api-Key TU_API_KEY"
```

## Tipos de conexión

Una empresa puede tener una conexión tributaria (`type: "tax"`, `provider: "sii"`)
y una o más conexiones de banco (`type: "bank"`, `provider` con el banco:
`santander`, `estado`, `bci`…). `?type=tax` o `?type=bank` trae solo unas u
otras; `meta.total` cuenta las conexiones de ese tipo. Otro
valor responde `400`.

```bash
curl "https://api.tupana.ai/v2/connections/?type=bank" \
  -H "Authorization: Api-Key TU_API_KEY"
```

`source` dice de dónde salen los datos: `sii` en la conexión tributaria; en el
banco, `fintoc` (proveedor de bancos), `scraper` (conector propio de Tupana) o
`manual_upload` (cartolas subidas a mano). Para ti es informativo: las cuentas
y los movimientos se leen igual venga de donde venga.

## Estado

`status` es lo que le pasa a la conexión, en tu idioma:

| `status` | Qué significa | Qué hacer |
| --- | --- | --- |
| `active` | La conexión sirve y se está leyendo. | Nada. |
| `pending` | Banco por conector propio: todavía no terminó la primera lectura. | Esperar. |
| `requires_action` | La clave dejó de servir, o el banco pidió reconectar. | El usuario final reconecta la empresa con [Tupana Connect](/api-reference/v2/connect/tupana-connect). No hay nada que reintentar desde tu lado. |
| `degraded` | Banco: alguna cuenta quedó detenida tras fallos repetidos; las demás siguen. | Nada por tu lado; Tupana la revisa. Si persiste, reconectar. |
| `inactive` | Alguien la desactivó con `DELETE`. | Volver a conectar con Tupana Connect si hace falta. |

En las conexiones de banco el estado sale de la conexión bancaria misma, no
solo de la clave guardada: un link al que el banco le pidió volver a entrar es
`requires_action` aunque la clave no haya cambiado.
