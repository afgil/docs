---
title: "Reautorizar una conexión"
openapi: "api-reference/openapi-v2.json POST /connections/{connection_id}/reauthorizations/"
---

Vuelve a abrir [Tupana Connect](/api-reference/v2/connect/tupana-connect) para que el
usuario final entre de nuevo al banco de una conexión que ya existe. La sesión
sale apuntando a esa empresa y ese banco, así que el usuario se salta esos
pasos, y la conexión **conserva su `connection_id`**: cuando termine, sigue
siendo la misma `cred_…` en tu base.

Es lo que corresponde cuando una conexión de banco está en `requires_action`:
el banco pidió volver a entrar, o la clave cambió.

```bash
curl -X POST https://api.tupana.ai/v2/connections/cred_5028174639201/reauthorizations/ \
  -H "Authorization: Api-Key TU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "external_customer_id": "cus_9", "return_url": "https://tusaas.cl/bancos" }'
```

```json
{
  "connection_id": "cred_5028174639201",
  "company_id": "ment_3672486436546233854",
  "provider": "santander",
  "type": "bank",
  "status": "requires_action",
  "connect_session_id": "cses_8831027465012",
  "client_token": "cst_…",
  "widget_url": "https://developers.tupana.ai/connect?token=cst_…",
  "environment": "production",
  "expires_at": "2026-10-28T21:05:00-03:00"
}
```

Abre `widget_url` (o pasa `client_token` al widget, igual que en una sesión
nueva). El `client_token` es de un solo uso y dura 30 minutos.

## Qué pasa con la conexión

- Queda en `requires_action` hasta que el usuario reconecte, aunque la lectura
  anterior siguiera funcionando. Si no estaba ya en ese estado, recibes
  `connection.requires_action` una vez.
- Cuando el banco acepta la clave llega `connection.active` con el mismo
  `connection_id`.
- Si el usuario cierra el widget sin terminar, la conexión sigue en
  `requires_action`: puedes pedir otra reautorización.

## Conexión compartida

Una persona que opera varias empresas con el mismo login tiene **una**
conexión asociada a varias `company_id`. En ese caso indica cuál en el body:

```json
{ "company_id": "ment_3672486436546233854" }
```

Sin `company_id` responde `400` diciendo que la conexión cubre varias empresas.

## Errores

- `404`: esa conexión no existe para tu API key.
- `400`: la conexión es tributaria (una conexión del SII se vuelve a conectar
  con una sesión nueva de Tupana Connect), la conexión no tiene banco asociado, o
  falta `company_id`.
- `403`: una API key de sandbox no abre sesiones de producción.

<Warning>
Solo conexiones de banco. Para el SII, crea una sesión de Tupana Connect con
`capabilities: ["invoicing"]` o `["sii_data"]`.
</Warning>
