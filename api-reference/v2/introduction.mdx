# API v2

Cada recurso tiene un **public ID**: un string con prefijo de tipo y número
aleatorio (`ment_4829301923847`, `prun_7291048302917`) almacenado en la base
de datos. No es una codificación del ID interno — es un identificador propio,
imposible de enumerar.

## Principios de diseño

| Versión | ID | Ejemplo |
|---------|-----|---------|
| v1 | entero incremental | `1234` |
| **v2** | public ID (prefijo + aleatorio) | `ment_4829301923847` |

- El prefijo identifica el tipo de recurso sin ambigüedad: `ment_` es una
  empresa, `docu_` un documento, `prun_` un proceso de liquidación, `slip_`
  una liquidación, `empl_` un trabajador.
- El número es **aleatorio de 62 bits** — no revela volumen ni orden de
  creación, y no se puede adivinar el siguiente.

## Base URL

```
https://api.tupana.ai/api/v2/
```

## Autenticación

Idéntica a v1: API Key en el header `Authorization`.

```bash
Authorization: Api-Key TU_API_KEY
```

## v1 y v2 conviven

- **v1** sigue funcionando con enteros incrementales, sin cambios: los
  clientes actuales con API key no se tocan.
- **v2** usa exclusivamente el public ID, en entrada y salida.

El mismo recurso es accesible por ambas versiones — `1234` en v1 y
`ment_4829301923847` en v2 apuntan a la misma empresa.
