Aquí registramos cada cambio de la API de Tupana que se nota desde tu integración: endpoints nuevos, campos, eventos de webhook, tipos de documento, límites y cambios de comportamiento. Las fechas son las de salida a producción. Suscríbete por RSS para enterarte de cada novedad.

<Update label="20 de octubre de 2026" description="SDKs, MCP y documentación">
  - SDKs oficiales publicados en npm ([`tupana`](https://www.npmjs.com/package/tupana)) y PyPI ([`tupana`](https://pypi.org/project/tupana/)): `npm install tupana` para Node.js y TypeScript, `pip install tupana` para Python. Versión 0.1.0, con código abierto en [tupana-ai/tupana-node](https://github.com/tupana-ai/tupana-node) y [tupana-ai/tupana-python](https://github.com/tupana-ai/tupana-python). Ver [SDKs](/sdks/introduccion).
  - El servidor MCP de Tupana ahora tiene repositorio público: [tupana-ai/tupana-mcp](https://github.com/tupana-ai/tupana-mcp). Además está publicado en el registro oficial de servidores MCP como `io.github.tupana-ai/tupana`. Ver [Servidor MCP](/user-guide/mcp).
  - Repositorio de ejemplos listos para usar: [tupana-ai/tupana-examples](https://github.com/tupana-ai/tupana-examples) (Next.js, emisión masiva desde Excel, receptores de webhooks, link de pago y un agente de IA que factura pidiendo tu confirmación).
  - Nueva guía [Tu primera llamada en 2 minutos](/quickstart) con sandbox.
  - Guías por tarea: [emitir en lote](/guias/emision-masiva), [webhooks](/guias/webhooks), [link de pago](/guias/link-de-pago), [cesiones](/guias/cesiones) y [varias empresas](/guias/multiempresa).
  - Nueva sección [Agentes de IA](/agentes/introduccion) (MCP y tool calling), [Precios](/precios) y [Cómo elegir una API de facturación](/elegir-api-facturacion-electronica).
  - `llms-full.txt` ahora incluye la referencia completa de la API v2 en Markdown.
</Update>

<Update label="19 de octubre de 2026" description="MCP y documentos programados">
  - Servidor MCP: `create_sale_invoice` deja la factura como borrador y la emisión pasa por revisar su vista previa (`get_document_preview` y luego `emit_document`). La herramienta acepta referencias (orden de compra 801, HES), forma de pago y vencimiento (`payment_method`, `due_date`, `due_days`). `get_document_link` entrega el PDF oficial del SII. Ver [Servidor MCP](/user-guide/mcp).
  - [Documentos programados](/api-reference/v2/scheduled-documents/create): cada línea puede llevar su propia `currency`; si no la envías, se usa la moneda del documento.
</Update>

<Update label="15 de octubre de 2026" description="Guía de despacho y libros del SII">
  - Guía de despacho (DTE 52): campos de la Resolución Exenta N°154 del SII, con avisos en la respuesta de la API hasta la fecha de entrada en vigencia. Ver [Documentos](/user-guide/documents).
  - Anulación de guías con motivo: [`POST /v2/documents/{id}/states/`](/api-reference/v2/document-states/create) con `event_code` `ANNULLED` y `reason`.
  - Con el facturador gratuito del SII, el destino y el tipo de despacho de la guía se aceptan y se imprimen como texto en el detalle, en vez de rechazar el documento.
  - Nuevo endpoint de [detalle del libro de compras y ventas](/api-reference/v2/book-documents/list) (`/v1/book-documents/` y `/v2/book-documents/`): una fila por documento del Registro de Compras y Ventas con sus montos e impuestos.
</Update>

<Update label="8 de octubre de 2026" description="Webhooks">
  - Si no eliges `api_version` al crear un webhook, se usa la de la ruta: los creados por `/v1/webhooks/` nacen en versión 1 (ids enteros) y los creados por `/v2/webhooks/` en versión 2 (ids públicos `docu_…`, `ment_…`).
  - Nuevos [`GET`](/api-reference/v2/webhooks-pages/get), [`PATCH`](/api-reference/v2/webhooks-pages/update) y `DELETE` sobre `/v2/webhooks/{id}/`. Con `PATCH` subes un webhook existente a `api_version: 2`.
</Update>

<Update label="2 de octubre de 2026" description="Exportación">
  - País y nacionalidad del receptor en facturas de exportación, separados del país de destino. Ver [Países de exportación](/user-guide/export-countries).
</Update>

<Update label="30 de septiembre de 2026" description="Idempotencia">
  - Al reenviar un lote con el mismo `Idempotency-Key`, la respuesta incluye el `batch_id` del lote original.
  - El header `Idempotency-Key` se puede enviar desde el navegador (permitido en CORS).
</Update>

<Update label="29 de septiembre de 2026" description="Webhooks">
  - Nuevo campo `environment` en los webhooks: `production`, `sandbox` o `both` (por defecto). Así un mismo endpoint recibe sólo los eventos del ambiente que elijas. Ver [Webhooks](/user-guide/webhooks).
</Update>

<Update label="28 de septiembre de 2026" description="Conexiones y consola de developers">
  - Nuevos endpoints de [conexiones](/api-reference/v2/connections/list): listar y [desactivar](/api-reference/v2/connections/delete) las empresas conectadas. `/v2/connections/` acepta API key y sesión de usuario.
  - La conexión de un banco por Tupana Connect se da por activa cuando el banco entrega las cuentas, y en ese momento se envía el webhook `connection.active` (o `connection.requires_action`).
  - Consola de developers en [developers.tupana.ai/console](https://developers.tupana.ai/console): crea tu cuenta y tus API keys.
</Update>

<Update label="25 de septiembre de 2026" description="Bases de datos gratuitas y MCP">
  - [Bases de datos gratuitas](/api-reference/v2/free-databases/introduction): nómina de empresas del SII consultable con cualquier API key, con [búsqueda](/api-reference/v2/free-databases/companies-search), [historia por RUT](/api-reference/v2/free-databases/company-history), [resumen](/api-reference/v2/free-databases/companies-summary) y [metadatos](/api-reference/v2/free-databases/companies-metadata).
  - El servidor MCP enseña a construir facturación dentro de otro SaaS: flujo de emisión, especificación de la interfaz, búsqueda de clientes por RUT y reglas de validación. Ver [Agentes de IA](/agentes/introduccion).
</Update>

<Update label="24 de septiembre de 2026" description="Tupana Connect y emisión v2">
  - [Tupana Connect](/api-reference/v2/connect/tupana-connect): el widget hospedado con el que tus usuarios conectan su empresa (SII y bancos). En v2 reemplaza la creación de credenciales por API. Nuevos eventos de webhook `connection.active` y `connection.requires_action`.
  - `additional_info` en documentos (creación, detalle, listado y webhooks). Se imprime en el PDF y queda fija cuando el documento tiene folio.
  - [Emisión v2](/api-reference/v2/documents/batch): ya no es necesario enviar `master_entity_id`; el emisor se toma de `document_issuer`. En sandbox no se exige credencial del SII y la vista previa del borrador funciona igual que en producción.
</Update>

<Update label="23 de septiembre de 2026" description="Sandbox y documentos">
  - Con una API key de sandbox, el [listado de documentos](/api-reference/v2/documents/list) devuelve los documentos de producción y los de sandbox de la empresa.
  - Las respuestas v2 de documentos vuelven a incluir el `json_param` que enviaste al crear.
</Update>

<Update label="21 de septiembre de 2026" description="Cesiones">
  - Un [lote de cesión](/api-reference/v2/cessions/batch) lo puede pedir quien tiene hoy la factura, no sólo su emisor original.
</Update>

<Update label="17 de septiembre de 2026" description="API v2">
  - La API v2 responde en `https://api.tupana.ai/v2/…`, con el mismo estilo de URL que la v1. Ver [Introducción a la API v2](/api-reference/v2/introduction).
</Update>

<Update label="15 de septiembre de 2026" description="Guía de despacho y validación">
  - Emisión de guías de despacho (DTE 52) con transporte, destino, despacho, datos de Aduana y líneas exentas. Las guías de exportación aceptan el código de traslado excepcional (`transfer_issuer_code`) y su resolución. Ver [Códigos de transporte y Aduana](/user-guide/transport-codes).
  - El lote de emisión avisa los campos desconocidos en `warnings`. Las API keys nuevas validan en modo estricto y responden `422` antes de crear el lote; las existentes quedan en modo aviso.
  - El detalle de un lote acepta el id público o el UUID.
  - La API v1 mantiene sus ids enteros: las integraciones existentes no cambian.
</Update>

<Update label="12 de septiembre de 2026" description="API v2">
  - Lanzamiento de la API v2: ids públicos con prefijo (`docu_…`, `ment_…`), listas paginadas uniformes, selección de campos y [taxonomía de errores](/api-reference/v2/errors) con códigos estables (`parameter_*`, `resource_missing` y códigos propios de cesiones y recaudación).
  - Las respuestas v2 no exponen estado interno del servidor (trazas crudas del SII, registros de actualización).
  - Reenviar un lote con un `Idempotency-Key` ya procesado devuelve el lote original (`200`) sin volver a emitir al SII.
</Update>

<Update label="9 de septiembre de 2026" description="Exportación">

<Update label="8 de septiembre de 2026" description="Boletas">
  - Boleta de espectáculo por cuenta de terceros: la línea de detalle acepta `show_item_type`, `principal_rut` y un bloque `ticket`, en `POST /v1/documents/batch/` y en v2.
</Update>

<Update label="4 de septiembre de 2026" description="Exportación y folios">
  - Facturas de exportación: el tipo de cambio se alinea con la fecha de emisión del DTE y los puertos de embarque y desembarque se completan desde el país de destino.
  - Los errores de folios traen `error_code` (vocabulario cerrado para decidir si reintentar) y `sii_code`. Ver [Códigos de error de folios](/api-reference/folios/errors).
</Update>

<Update label="1 de septiembre de 2026" description="Límites">
  - La búsqueda por `folio` en el listado de documentos tiene un límite de 30 consultas por hora por API key. Al superarlo, la API responde `429`.
</Update>

<Update label="28 de agosto de 2026" description="Documentos y folios">
  - Las referencias de notas de crédito y débito aceptan `reference_code` (CodRef del SII: 1 anula, 2 corrige texto, 3 corrige montos).
  - Documentos programados: reajuste del precio por IPC cada cierta cantidad de meses.
  - Las consultas de folios al SII pasan a ser un recurso propio: [`/v2/folio-queries/`](/api-reference/v2/folios/query-create).
</Update>

<Update label="27 de agosto de 2026" description="Folios, referencias y límites">
  - [API de folios](/api-reference/v2/folios/availability): disponibilidad, timbraje de folios y retiro del CAF, con los webhooks `folio_request.completed`, `folio_request.failed` y `folio_request.authorized_without_caf`.
  - Las referencias aceptan un tipo de documento definido por tu empresa (hasta 3 caracteres, por ejemplo `HES`).
  - El [detalle de un documento](/api-reference/documents/get) tiene un límite de 600 consultas por hora por API key y de 60 por hora sobre un mismo documento. Al superarlo, la API responde `429`; para enterarte de cambios de estado usa [webhooks](/user-guide/webhooks).
</Update>

<Update label="25 de agosto de 2026" description="Sandbox">
  - Los documentos de sandbox se timbran con un XML de la misma estructura que en producción y un PDF real con marca de agua de vista previa.
</Update>

<Update label="19 de agosto de 2026" description="Webhooks">
  - Nuevo evento `document.trace_updated`: un aviso por cada evento nuevo de la traza del SII (acuses, reclamos, rechazos), tanto de documentos emitidos como recibidos. El payload trae `role` para saber de qué lado estás.
</Update>

<Update label="18 de agosto de 2026" description="Documentos">

<Update label="13 de agosto de 2026" description="Webhooks">

  - Un webhook se desactiva automáticamente sólo ante una caída sostenida de tu endpoint (100 fallos seguidos), no por un error puntual.
</Update>
